# 装车与新家分成两套空间

2026-11-02

## 状态

现在只有一条结果：照片变成报价，再自动摆进所选车型。页面只能旋转观看，不能改位置。新家怎么摆，没有单独的空间。

## 问题

搬家有两段不同的操作。装车要在车厢里堆叠。到了新家，要按房子的平面把家具放在地板上。两段不能共用同一个只读车厢。

## 技术框架

- 后端继续用 Python、FastAPI 和 Pydantic。不增加数据库、账号或前端构建工具。
- 报价公式保持不变。视觉模型仍然只产出家具清单。
- 三维场景使用 Three.js r170 的 ES 模块，文件放在 `web/vendor/three.module.js`，由页面的 import map 加载。不使用打包器，也不从外网加载脚本。r170 已经不再提供可直接用 script 标签引入的构建。
- 平面图在页面的二维画布上绘制。墙和地板的盒子由 Python 生成，页面只按坐标绘制。
- 鼠标拖动时，页面只移动预览。松手后把水平位置和 90 度转角交给服务端。支撑高度、越界、重叠和房间边界都在 Python 里判定，测试不访问网络。

## 两套逻辑

1. 装车。输入长、宽、高生成一节车厢。散装家具和纸箱可以拖动、水平旋转，并叠在有支撑的物体上。放不下的留在待装列表。
2. 新家。用矩形房间画平面图，按墙高挤出三维空间。家具按自身外形放在某一间的地板上，不叠放，也不换成纸箱。

自动摆放仍然给报价和 `/view` 使用。手动结果不改费用。

## 开发顺序

1. 在本文件、`docs/design.md` 和 `docs/architecture.md` 写清规则。
2. 把车厢尺寸限制和新家墙体参数放进 `config/config.yaml`。
3. 为摆放块补稳定编号，并实现自定义车厢、拖拽落点和平面图挤压。
4. 增加不调用模型的 HTTP 接口和两个页面。
5. 用规划测试锁住落点，再在浏览器里拖动物体。

## 落地

- `src/layout.py` 负责初始摆放和自定义车厢的第一轮自动放入。
- `src/cargo_edit.py` 负责装车时的一次移动。
- `src/home.py` 负责平面图、墙体和新家落点。
- `src/agent.py` 只编排这些调用。
- `web/pack.html` 和 `web/home.html` 分别是两个页面。
